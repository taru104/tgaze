## 2. 手順

1. **データ【確定】:**
   - 7 月の REPORT8 で使った MPIIFaceGaze は、このPCにはありませんでした（REPORT8 のスクリプトは Windows の `.venv/Scripts/python.exe` 前提で、`~/tgaze/MPIIFaceGaze` も `cache/` もありません。HDD も探しました）。
   - 公式の配布元 `https://datasets.d2.mpi-inf.mpg.de/MPIIGaze/MPIIFaceGaze.zip`（942,343,290 バイト）からダウンロードして、データ用 HDD の `/run/media/rtarutani/3AB8C6C2B8C67C3F/tarutani/datasets/MPIIFaceGaze/` に展開しました。
   - 注釈の列は同梱の readme で確認しました（2〜3 列目 = 画面上の注視点 px、22〜24 列目 = fc、25〜27 列目 = gt、カメラ座標、mm）。
2. **ランドマーク**（`benchmarks/mpii_m8_extract.py`）【確定】:
   - キットと同じく画像を左右反転（`cv2.flip(frame, 1)`）し、同じ `face_landmarker.task`（CPU、num_faces 1、信頼度 0.5）で 478 点を取りました。
   - 顔が見つからなかったのは 86 枚。p01 の 7 枚は 320×240 で、Camera.mat の解像度（1280×720）と違うので除外しました。有効 37,574 / 37,667 枚（REPORT8 は 37,595 枚）。
3. **本番の特徴量と M8**（`benchmarks/mpii_m8_eval.py`）【確定】:
   - キットの `m8_cpu.OfflineM8("model", K, w=1280, h=720)` をそのまま使いました。
   - K は**その人の** Camera.mat の `cameraMatrix` です。rich16d の solvePnP も Kabsch の特徴量も、この K で計算されます（キットと同じく左右反転用の K）。
   - 出力は M8 の学習用画面（「このPCの画面」= `final_model_preprocessing.json` の display）上の uv です。
4. **uv → 3D 点** 【確定】:
   - キットの `M8Runtime.angular_error_deg` と同じ式（中心 + u × 14.53 cm × 右 + v × 9.45 cm × 上）で、反転カメラ座標の 3D 点にし、x の符号を戻して通常のカメラ座標（mm）にしました。
5. **目の中心** 【暫定】（仮定を含む）:
   - MediaPipe の metric な標準顔モデル（`canonical_face_model.obj`、cm 単位、MediaPipe の GitHub から取得、Apache-2.0）の 44 点（キットの RIGID 40 点 + 目尻・目頭 4 点）を、その人の K で solvePnP しました（SQPNP のあと ITERATIVE、歪みは使わない）。
   - 反転画像では MediaPipe が「鏡に映った顔」としてラベルを付けるので、PnP は反転座標・反転 K で解いてから x を戻しています。
   - 左右の眼球の中心 = 目尻と目頭の中点から 1.2 cm 奥（仮定）、その中点を視線の始点 E にしました。
   - 再投影誤差の中央値は人ごとに 2.5〜8.4 px。E は注釈の fc より、人ごとの中央値の平均で 3.5 cm ほど奥（0.4〜6.9 cm）、2 cm ほど上です（fc は目と口の 6 点の中心なので、上下にずれるのは当然）。奥行きの差は標準顔モデルの大きさと MPII の顔モデルの違いによるものと思われます【暫定】。始点を fc にしても結果はほぼ同じです（§1）。
6. **その人の画面上の予測点** 【確定】:
   - 視線 E → 3D 点を、monitorPose.mat（画面 → カメラの回転・平行移動、画面の x は右、y は下、mm）の平面と交差させ、screenSize.mat で mm に直しました。
   - 正解は注釈の画面 px × (width_mm / width_pixel, height_mm / height_pixel) です。
7. **指標** 【確定】:
   - 人ごとに、cm の中央値と平均、角度の中央値と RMSE を出しました。
   - 16 サンプルのアフィン補正は `exp64_lopo_kshot.py` と同じです。その人の有効フレームからランダムに 16 枚（seed `RandomState(1000*s+7)`、s = 0〜4 の 5 回）、画面正規化座標で `Ridge(alpha=1e-3)` の 2×2 + 2 アフィンを当てはめ、残りで評価しました。5 回分は、中央値は中央値を、RMSE は平均を取りました。

評価のコードを使わずに、別のコードで手計算しました。結果は `handcheck_p00.txt` と同じ内容です。すべて【確定】。

## 4. できなかったこと・違い

- **旧手法の数字の再計算【確認できない】:** 旧手法のキャッシュ（`cache/mpii_full.npz`）と学習済みの状態はこのPCに無く、REPORT8 の値をそのまま並べています。同じ有効フレームでの比較にはなっていません（旧 37,595 枚、今回 37,574 枚）。
- **旧手法との処理の違い【確定】（コードで確認）:**
  - 旧手法は画像を反転せず、rich16d のカメラ行列も既定値（f = 画像の幅、主点 = 中心）でした。今回は本番キットと同じく反転し、その人の K を使っています。
  - 角度の始点（fc）、補正の方法（16 枚、5 seed、Ridge 1e-3）、集計の方法は旧手法に合わせました。
- **MediaPipe のモード:** キットはライブで VIDEO モードですが、MPII は連続した動画ではないので IMAGE モードを使いました。ライブの追跡とは結果が少し違う可能性があります【確認できない】。
- **レンズの歪み:** Camera.mat の `distCoeffs` は使っていません（キットも歪みを使わないため）。
- **目の中心の仮定【暫定】:** 標準顔モデルの大きさ、眼球の中心を目尻と目頭の中点から 1.2 cm 奥としたこと。始点を注釈の fc にしても結果がほぼ同じなので、全体の数字への影響は小さい【確定】。
- **縦のずれの原因の切り分け【確認できない】:** 配置・頭の向き・見た目のどれが効いているかは調べていません。
- **Mac で動かしての確認はしていません。** 計算はこのPC（Linux、CPU の onnxruntime）だけです。
- **EyePCA 版や Phase 8 のモデル**（models_alt）は対象外です（依頼は本番モデルのみ）。
